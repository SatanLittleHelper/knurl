# Задача 3: Миграции базы данных

**Что строим:** SQL-схему всех таблиц через goose.

---

## Зачем нужны миграции

Миграции — это версионированные изменения схемы БД. Вместо того чтобы руками выполнять SQL в БД, ты пишешь файл миграции. goose отслеживает какие миграции уже применены и применяет только новые.

Это как git, но для схемы базы данных:
- Легко воспроизвести схему на новой машине (`make migrate-up`)
- Легко откатить изменение (`make migrate-down`)
- История изменений хранится в коде

**Почему goose, а не GORM AutoMigrate?**
GORM умеет автоматически создавать таблицы из стракт-моделей (`db.AutoMigrate(&User{})`). Но это опасно в продакшене — GORM никогда не удаляет колонки автоматически и плохо справляется со сложными изменениями. Явные SQL-миграции дают полный контроль.

## Схема данных

```
users
  └── workout_plans (user_id → users.id)
        └── workout_days (plan_id → workout_plans.id)
              └── planned_exercises (day_id → workout_days.id, exercise_id → exercises.id)

exercises (кэш внешнего API)

workout_sessions (user_id → users.id, plan_id → workout_plans.id, day_id → workout_days.id)
  └── set_logs (session_id → workout_sessions.id, exercise_id → exercises.id)
```

## Шаги

- [ ] **Шаг 1: Создать `001_users.sql`**

```sql
-- +goose Up
-- Эти комментарии обязательны для goose: Up — применить, Down — откатить.

CREATE TABLE users (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(), -- UUID генерируется автоматически в PostgreSQL
    email         TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,                             -- храним хэш, не сам пароль
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- +goose Down
DROP TABLE users;
```

- [ ] **Шаг 2: Создать `002_exercises.sql`**

```sql
-- +goose Up
CREATE TABLE exercises (
    id            TEXT PRIMARY KEY,        -- ID берём из внешнего API, поэтому TEXT а не UUID
    name          TEXT NOT NULL,
    muscle_group  TEXT NOT NULL,
    equipment     TEXT,
    instructions  TEXT,
    gif_url       TEXT,
    cached_at     TIMESTAMPTZ NOT NULL DEFAULT NOW() -- когда последний раз обновляли кэш
);

-- +goose Down
DROP TABLE exercises;
```

- [ ] **Шаг 3: Создать `003_plans.sql`**

```sql
-- +goose Up
CREATE TABLE workout_plans (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE, -- при удалении пользователя удаляются его планы
    name        TEXT NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at  TIMESTAMPTZ  -- NULL = не удалён. Мягкое удаление: запись остаётся в БД но помечается удалённой
);

CREATE TABLE workout_days (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    plan_id     UUID NOT NULL REFERENCES workout_plans(id) ON DELETE CASCADE,
    day_of_week SMALLINT NOT NULL CHECK (day_of_week BETWEEN 0 AND 6), -- 0=воскресенье, 1=понедельник, ..., 6=суббота
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at  TIMESTAMPTZ
);

CREATE TABLE planned_exercises (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    day_id        UUID NOT NULL REFERENCES workout_days(id) ON DELETE CASCADE,
    exercise_id   TEXT NOT NULL REFERENCES exercises(id),
    sets          SMALLINT NOT NULL,
    reps          SMALLINT NOT NULL,
    target_weight NUMERIC(6,2), -- NULL если вес не задан (упражнения с весом тела)
    position      SMALLINT NOT NULL, -- порядок упражнения в дне
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at    TIMESTAMPTZ
);

-- +goose Down
DROP TABLE planned_exercises;
DROP TABLE workout_days;
DROP TABLE workout_plans;
```

- [ ] **Шаг 4: Создать `004_sessions.sql`**

```sql
-- +goose Up
CREATE TABLE workout_sessions (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    plan_id     UUID REFERENCES workout_plans(id), -- NULL если тренировка без плана
    day_id      UUID REFERENCES workout_days(id),  -- NULL если тренировка без плана
    started_at  TIMESTAMPTZ NOT NULL,
    finished_at TIMESTAMPTZ,    -- NULL пока тренировка не завершена
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at  TIMESTAMPTZ
);

-- +goose Down
DROP TABLE workout_sessions;
```

- [ ] **Шаг 5: Создать `005_sets.sql`**

```sql
-- +goose Up
CREATE TABLE set_logs (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id   UUID NOT NULL REFERENCES workout_sessions(id) ON DELETE CASCADE,
    exercise_id  TEXT NOT NULL REFERENCES exercises(id),
    set_number   SMALLINT NOT NULL,   -- номер подхода (1, 2, 3...)
    reps         SMALLINT NOT NULL,
    weight       NUMERIC(6,2),        -- NULL для упражнений с весом тела
    completed_at TIMESTAMPTZ NOT NULL,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at   TIMESTAMPTZ
);

-- +goose Down
DROP TABLE set_logs;
```
