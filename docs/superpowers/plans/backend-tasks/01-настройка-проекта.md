# Задача 1: Настройка проекта

**Что строим:** Go-модуль, структура папок, чтение конфига из переменных окружения, минимальная точка входа.

---

## Зачем это нужно

В Go проект начинается с `go.mod` — это аналог `package.json` в Node.js. Здесь объявляется имя модуля и версия Go. Все пути импортов в коде строятся относительно имени модуля.

Структура папок — важная часть Go-проекта:
- `cmd/api/` — точка входа. В Go принято держать `main.go` в папке `cmd/<имя>`, потому что у проекта может быть несколько исполняемых программ (например, `cmd/api` и `cmd/migrate`)
- `internal/` — приватный код приложения. Go запрещает импортировать пакеты из `internal/` снаружи модуля — это встроенная защита от нежелательных зависимостей
- `internal/config/` — чтение переменных окружения. Лучше иметь одно место, откуда весь код берёт конфиг, а не раскидывать `os.Getenv` по всему проекту

## Шаги

- [ ] **Шаг 1: Инициализировать Go-модуль**

Выполнить из папки `backend/`:

```bash
cd backend
go mod init github.com/satanlittlehelper/knurl/backend
```

Это создаст файл `go.mod`. Имя модуля (`github.com/satanlittlehelper/knurl/backend`) — это то, как другие файлы проекта будут импортировать наши пакеты. Например: `import "github.com/satanlittlehelper/knurl/backend/internal/config"`.

- [ ] **Шаг 2: Установить зависимости**

```bash
go get github.com/go-chi/chi/v5
go get gorm.io/gorm
go get gorm.io/driver/postgres
go get github.com/pressly/goose/v3
go get github.com/golang-jwt/jwt/v5
go get github.com/joho/godotenv
go get github.com/google/uuid
go get golang.org/x/crypto
```

`go get` — аналог `npm install`. Скачивает зависимости и добавляет их в `go.mod` и `go.sum`.

- [ ] **Шаг 3: Создать `.env.example`**

```env
DATABASE_URL=postgres://postgres:postgres@localhost:5432/knurl?sslmode=disable
JWT_SECRET=change-me-in-production
PORT=8080
```

Это шаблон для разработчика — нужно скопировать в `.env` и заполнить своими значениями. Сам `.env` никогда не коммитится в git (содержит секреты).

- [ ] **Шаг 4: Создать `internal/config/config.go`**

```go
package config

import "os"

// Config хранит все параметры приложения, прочитанные из переменных окружения.
// Такой подход называется "12-factor app" — конфигурация отделена от кода.
type Config struct {
	DatabaseURL string
	JWTSecret   string
	Port        string
}

// Load читает переменные окружения и возвращает Config.
// Если обязательная переменная не задана — паникует при старте.
// Лучше упасть сразу, чем получить непонятную ошибку во время работы.
func Load() Config {
	return Config{
		DatabaseURL: mustEnv("DATABASE_URL"),
		JWTSecret:   mustEnv("JWT_SECRET"),
		Port:        getEnv("PORT", "8080"),
	}
}

// mustEnv возвращает значение переменной окружения или паникует если она не задана.
func mustEnv(key string) string {
	v := os.Getenv(key)
	if v == "" {
		panic("missing required env var: " + key)
	}
	return v
}

// getEnv возвращает значение переменной окружения или fallback если она не задана.
func getEnv(key, fallback string) string {
	if v := os.Getenv(key); v != "" {
		return v
	}
	return fallback
}
```

- [ ] **Шаг 5: Создать `cmd/api/main.go`**

```go
package main

import (
	"fmt"
	"log"
	"net/http"

	"github.com/go-chi/chi/v5"
	"github.com/joho/godotenv"
	"github.com/satanlittlehelper/knurl/backend/internal/config"
)

// main — точка входа программы. Здесь происходит:
// 1. Загрузка конфига
// 2. Создание всех зависимостей (БД, сервисы, обработчики)
// 3. Регистрация маршрутов
// 4. Запуск HTTP-сервера
//
// Такой подход называется "composition root" — всё собирается в одном месте.
// Сами сервисы не знают как создаются их зависимости — они просто получают их.
func main() {
	// godotenv.Load() читает файл .env и добавляет переменные в окружение процесса.
	// Игнорируем ошибку (_ =) — в продакшене .env не нужен, там переменные задаются иначе.
	_ = godotenv.Load()

	cfg := config.Load()

	r := chi.NewRouter()

	// Healthcheck — простой эндпоинт для проверки что сервер жив.
	// Используется load balancer'ами и мониторингом.
	r.Get("/health", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})

	addr := fmt.Sprintf(":%s", cfg.Port)
	log.Printf("server started on %s", addr)
	log.Fatal(http.ListenAndServe(addr, r))
}
```

- [ ] **Шаг 6: Создать `Makefile`**

```makefile
.PHONY: run migrate-up migrate-down

# Запуск сервера
run:
	go run ./cmd/api

# Применить все новые миграции
migrate-up:
	go run github.com/pressly/goose/v3/cmd/goose -dir internal/db/migrations postgres "$(DATABASE_URL)" up

# Откатить последнюю миграцию
migrate-down:
	go run github.com/pressly/goose/v3/cmd/goose -dir internal/db/migrations postgres "$(DATABASE_URL)" down
```

Makefile — удобный способ запускать частые команды. `make run` вместо длинной команды `go run ./cmd/api`.

```bash
go build ./...
```

`go build ./...` компилирует все пакеты проекта. Ожидаемо: без ошибок.
