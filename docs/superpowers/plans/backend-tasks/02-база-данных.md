# Задача 2: База данных

**Что строим:** Docker Compose для локального PostgreSQL, подключение к БД через GORM.

---

## Зачем GORM, а не чистый SQL

**Чистый SQL (pgx)** — пишешь SQL-запросы вручную, результаты вручную сканируешь в переменные. Много кода, легко ошибиться.

**GORM** — ORM (Object-Relational Mapper). Ты описываешь структуры данных (Go-стракты), а GORM сам генерирует SQL, выполняет запросы и заполняет стракты результатами. Концептуально похож на TypeORM или Prisma из мира TypeScript/Node.js.

Пример разницы — получить пользователя по email:

```go
// Чистый SQL (pgx):
var id uuid.UUID
var hash string
err := pool.QueryRow(ctx, "SELECT id, password_hash FROM users WHERE email = $1", email).Scan(&id, &hash)

// GORM:
var user User
err := db.Where("email = ?", email).First(&user).Error
// user.ID и user.PasswordHash заполнены автоматически
```

---

## Зачем подключение к БД делается в `main`

В Go принято передавать зависимости явно ("dependency injection"). `main` создаёт подключение к БД один раз и передаёт его во все сервисы, которым оно нужно. Сами сервисы не знают как создаётся `db` — они просто получают готовый объект и работают с ним.

Это даёт несколько преимуществ:
- Одно место для инициализации — легко менять конфиг
- Сервисы легко тестировать — можно передать тестовую БД
- Явные зависимости — сразу видно что нужно сервису

## Шаги

- [ ] **Шаг 1: Создать `docker-compose.yml`**

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_DB: knurl
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

`docker-compose.yml` описывает локальное окружение для разработки. `volumes` сохраняет данные БД между перезапусками контейнера.

- [ ] **Шаг 2: Запустить PostgreSQL**

```bash
docker compose up -d
```

`-d` — запустить в фоне (detached). Ожидаемо: контейнер `db` запущен.

Проверить что работает:
```bash
docker compose ps
```
Ожидаемо: статус `running`.

- [ ] **Шаг 3: Создать `internal/db/db.go`**

```go
package db

import (
	"gorm.io/driver/postgres"
	"gorm.io/gorm"
	"gorm.io/gorm/logger"
)

// Connect создаёт подключение к PostgreSQL через GORM и проверяет его.
// Возвращает *gorm.DB — это основной объект GORM, через который делаются все запросы.
//
// dsn — Data Source Name, строка подключения вида:
// "postgres://user:password@host:port/dbname?sslmode=disable"
func Connect(dsn string) (*gorm.DB, error) {
	db, err := gorm.Open(postgres.Open(dsn), &gorm.Config{
		// В режиме разработки выводить SQL-запросы в лог — удобно для отладки.
		// В продакшене заменить на logger.Silent.
		Logger: logger.Default.LogMode(logger.Info),
	})
	if err != nil {
		return nil, err
	}

	// Проверяем что соединение работает — получаем объект sql.DB и пингуем.
	sqlDB, err := db.DB()
	if err != nil {
		return nil, err
	}
	return db, sqlDB.Ping()
}
```

- [ ] **Шаг 4: Обновить `cmd/api/main.go` — добавить подключение к БД**

```go
package main

import (
	"fmt"
	"log"
	"net/http"

	"github.com/go-chi/chi/v5"
	"github.com/joho/godotenv"
	"github.com/satanlittlehelper/knurl/backend/internal/config"
	"github.com/satanlittlehelper/knurl/backend/internal/db"
)

func main() {
	_ = godotenv.Load()
	cfg := config.Load()

	// Создаём подключение к БД.
	// Если БД недоступна — лучше упасть сразу при старте, чем работать в полуживом состоянии.
	database, err := db.Connect(cfg.DatabaseURL)
	if err != nil {
		log.Fatalf("db connect: %v", err)
	}

	// _ = database пока что заглушает ошибку "переменная не используется".
	// Когда добавим сервисы — будем передавать database в них.
	_ = database

	r := chi.NewRouter()
	r.Get("/health", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})

	addr := fmt.Sprintf(":%s", cfg.Port)
	log.Printf("server started on %s", addr)
	log.Fatal(http.ListenAndServe(addr, r))
}
```

- [ ] **Шаг 5: Скопировать `.env.example` в `.env` и запустить сервер**

```bash
cp .env.example .env
make run
```

Ожидаемо: в терминале `server started on :8080` и GORM выводит информацию о подключении без ошибок.
